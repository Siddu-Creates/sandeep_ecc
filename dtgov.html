Case Study 1

Remote Administration

DTGOV's remote administration system needs an upgrade for a growing number of cloud consumers and a wider variety of requests.

Self-provisioning

  • Consumers provision virtual servers and virtual storage devices themselves
  • Interoperates with the VIM platform's proprietary API

Single sign-on

  • One mechanism to centrally authorize cloud consumers
  • Central control of consumer access

Exposed API

  • Provision, start, stop and release
  • Scale up and down
  • Replicate virtual servers and storage
Result: a new self-service portal and an extended usage and administration portal
Case Study 2

Resource Management

An extension of the new VIM product DTGOV purchased. Pick a topic:

Resources

  • Flexible allocation of pooled IT resources across different data centers
  • Management of cloud consumer databases
  • Isolation of virtual IT resources at logical perimeter networks

Images and scaling

  • Template virtual server image inventory, ready for immediate instantiation
  • Automated replication ("snapshotting") of images for virtual server creation
  • Automated up-down scaling by usage thresholds, enabling live VM migration among physical servers

APIs

  • Create and manage virtual servers and virtual storage devices
  • Create network access control rules
  • Up-down scale virtual IT resources
  • Migrate and replicate resources across multiple data centers

Integration

  • Single sign-on through an LDAP interface
  • Custom SNMP command scripts work with network management tools to establish isolated virtual networks across multiple data centers
Case Study 3

SLA Management

The SLA management system works with the existing VIM, so administrators can monitor the availability of hosted IT resources through SLA monitors. Predefined reports appear on custom dashboards.

Per-Data Center Availability

Public on DTGOV's corporate cloud portal. Shows the real-time operational condition of each group of IT resources at each data center.

Per-Consumer Availability

Real-time condition of individual IT resources. Only the cloud provider and the consumer who leases or owns them can see it.

Per-Consumer SLA Report

Summarizes SLA statistics for a consumer's IT resources, including downtimes and other timestamped SLA events.

How SLA events travel

SLA monitorsGenerate events about physical and virtual IT resources
SNMP agentCustom agent receives the notifications
VIM APILinks each event to the affected virtual resource
Event databaseStores server and network downtimes
REST APIConnects to central remote administration
A batch service sends downtime data to billing, which becomes credit on usage fees
